# Changelog

Every notable change to StashBin is documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- MIT licence.
- End-to-end encryption in the browser: AES-256-GCM with a key derived by PBKDF2-SHA256 (310,000 iterations); the key travels in the URL's `#` fragment and never reaches the server.
- Secret creation restricted to authenticated users (PHP sessions, CSRF protection).
- Authentication can be disabled through `config.php`'s `auth` setting, for an open instance whose access is already restricted some other way. It remains required by default: that is the whole point of the project. Disabled, creation and deletion become available to any visitor, `login.php` redirects to the creation page which announces the open mode, and the deletion link requires nothing but its token. Nothing else moves: browser-side encryption, the hashed deletion token, CSRF protection and hardening headers are all maintained, and a dedicated test suite (`tests/noauth.test.php`, 22 tests) checks that against a genuinely open instance.
- An inventory for each creator (`secrets.php`, linked from the creation page): every secret they made, named by the identifier its link carries, with its state — never read, read *n* times, destroyed after reading, deleted, expired — the date it was created and the one it disappeared on, the log of accesses it received, and a delete button while it still lives. Secrets are not readable from that page: their key never left the browser that created them, and the server has no way of getting it back.

  Nothing on that page describes a secret's content, not even a label: the entries are told apart by their identifier and their dates. A plaintext title was written and then dropped — it made the list easier to read, at the price of the one telling piece of metadata the server would have been able to read.

  Two things do follow, and they are worth stating plainly. Secrets now carry an `owner_id`, so the server knows which account created which secret, where it used to know nothing. And every access is logged with its date, the reader's IP address as the web server saw it — never as `X-Forwarded-For` claims it, since the reader writes that header themselves — and the browser they declared, which is usually the explanation when a single-use secret is spent before its recipient opens it: a chat application preloading the link. An instance without authentication records none of it: no owner, no log, no page.

  Deleting a secret, reading a single-use one and letting one expire no longer remove the row: the ciphertext is wiped and the row stays as a headstone, so the list can say what became of it. Dates are rendered in the reader's own timezone: the server writes UTC, since it cannot know where anyone is, and the browser rewrites it — served without JavaScript, they stay readable and say they are UTC. An entry carries a badge for what guards it — single use, password — read straight out of the payload's own `pwd` flag, which is in the clear because the reader has to be told before being asked for a password. Its owner removes it for good with "remove from history", or clears the lot with a single button — expired entries pile up on their own, and taking them away one at a time is exactly the chore it looks like. Neither touches a secret that is still live. A secret nobody owns is deleted outright, as before, along with its log.

- `config.php` now holds nothing but literal values, directly editable. The environment-variable overrides — `STASHBIN_DB` for the database path, `STASHBIN_AUTH` for authentication, `STASHBIN_LOCALE` for the fallback language — are gathered in `env_overrides()` in `src/bootstrap.php`, which only applies a variable when it is set and non-empty.
- `AUTH=0 ./containers/stashbin.sh up` starts a development instance without authentication.
- Public reading by link, with an optional password mixed into key derivation.
- The password chosen at creation can be shown, through an eye at the end of the field — an icon rather than a word, which would have taken the room the field needs. A password typed once behind dots and never read back locks a secret nobody can open any more: the reader is only told that one is expected, never which. It goes back under its dots on the next click, and starts hidden and empty for the next secret.
- Configurable expiry (1 hour, 1 day, 1 week, 1 month, never) with automatic purging of expired secrets.
- A specific date and time can be chosen instead of a preset lifetime. Picking "Specific date and time…" reveals two native fields — a date, which browsers open as a calendar, and a time, which they open as a clock or a spinner. They start on today at the time it is, so that only what usually changes has to be touched, and are refreshed whenever the instant they hold has fallen behind the clock. Their value is read in the visitor's own timezone and sent as a Unix timestamp.

  The instant is refused rather than corrected when it is already past or beyond year 9999 — a secret outliving what its author asked for is the one mistake here that cannot be taken back. Two lines of defence keep a past date from being encrypted at all: the date field's own `min`, and a check in the script for the browsers that validate nothing. The instant is read in the visitor's own timezone, which is also the one the inventory displays it back in.
- Burn after first reading, preceded by a confirmation screen so the secret is not consumed by accident.
- Deletion link handed to the creator.
- Account management from the command line (`bin/user.php`: `add`, `passwd`, `del`, `list`).
- SQLite storage with no external dependency, schema created automatically.
- Storage in **MariaDB** (or MySQL) for an instance that already runs one, SQLite remaining the default and the shipped configuration. `config.php`'s `db` setting takes an array — `driver`, `host` or `socket`, `port`, `name`, `user`, `pass` — instead of a path, and every field also has an environment variable (`STASHBIN_DB_DRIVER`, `_HOST`, …) for a container where the file is mounted read-only. A bare path still means SQLite and that file: an instance happy with it has nothing to learn.

  Everything an engine spells its own way lives in one file per engine in `src/db/` — the connection, the schema, and the three fragments of SQL the queries cannot write once: reading a JSON boolean, comparing a number, and ordering rows by insertion. Adding an engine means dropping a file there, as adding a language means dropping one in `src/lang/`. `src/bootstrap.php` knows that shape and nothing about any engine in particular.

  StashBin creates its tables on first use, never the database itself: that takes a privilege an application has no business holding. They are created under a binary collation, and that is not housekeeping — identifiers are case-sensitive, and under MySQL's usual case-insensitive default `aB3` and `Ab3` would be the same secret, which is one reader served another's ciphertext.

  The whole test set is played against both engines (`./tests/run.sh --db mariadb`), which is how three things that only ever break on one of them were found: `reads` is a reserved word in MariaDB, a `LIMIT` parameter is a syntax error there as soon as PDO quotes it, which it does whenever it prepares a statement itself, and InnoDB's default isolation level made twenty simultaneous readers of a single-use secret deadlock on the access log — each holding a shared lock on the gap the next one meant to write into. The MySQL driver asks for `READ COMMITTED`, which is also the level SQLite behaves at under WAL.
- Multilingual interface: English and French, chosen from the browser's `Accept-Language` header, falling back to `default_locale` (`en` by default, overridable through `STASHBIN_LOCALE`): a visitor none of whose requested languages is translated gets English. `src/lang/fr.php` remains the reference language, the one a partial translation borrows its missing keys from — the two roles are distinct. A regional tag falls back to its language (`fr-CA` → `fr`). The `?lang=` parameter forces the language of a page, with no cookie and no session. Adding a language means dropping a file into `src/lang/`: the code lists that directory. Responses carry `Vary: Accept-Language`.
- API errors now carry a stable `code` field (`not_found`, `unauthorized`, `bad_csrf`…) beside the message, which is translated: the JavaScript compares the code, never the text.
- Automatic light/dark theme, following the system preference.
- Moving between the creation page and the inventory is done with buttons rather than a row of links: "My secrets" and "Sign out" on one side, "Create a secret" on the other. They stay anchors under the styling — a middle click or a new tab has to keep working — and are drawn quietly, so that they never compete with the action each page exists for.
- `containers/` test bench: Apache + mod_php and nginx + PHP-FPM images, parameterised by PHP version (8.3 to 8.6), with the code mounted read-only and the SQLite database in a dedicated volume (path overridable through `STASHBIN_DB`). Both images carry `pdo_mysql` beside the built-in `pdo_sqlite`, and `DB=mariadb ./containers/stashbin.sh up` starts a MariaDB server beside the instance and points it there.
- `containers/stashbin.sh`: single driver for the test bench (`up`, `user`, `logs`, `down`, `reset`, `clean`, `list`, `test`). `clean` removes the containers, volumes and images the bench produced — and nothing else; `clean --all` adds the downloaded `php:*` base images. `user` relays `bin/user.php`'s subcommands (`add`, `passwd`, `del`, `list`) into the container, under the `www-data` identity. `test` replays the full application journey across all eight version × server combinations and fails if any of them regresses.
- Compatibility verified from PHP 8.1 to 8.6 (8.6 as a release candidate), under Apache as well as nginx: no deprecation and no warning.
- Complete test set (`tests/run.sh`): 278 tests across five suites — unit (functions in `src/bootstrap.php`), API (business rules), security (the guarantees the README makes), open instance (behaviour without authentication, played against a second container) and browser (end-to-end cryptography and interface journeys in Chromium). The runner starts a fresh instance, plays the suites and tears everything down; its exit code is 0 if and only if everything passes. `--db mariadb` plays the same suites against a MariaDB server started beside the instance. No Composer dependency: the assertions and the HTTP client fit in `tests/lib.php`.
- The cryptography of `public/assets/stashbin.js` is now covered: encrypt/decrypt round trips on varied texts, rejection of an altered password, key, vector or ciphertext, and checks on the announced sizes (256-bit key, 128-bit salt, 96-bit vector, 310,000 iterations).
- Security headers: strict CSP, `X-Content-Type-Options`, `Referrer-Policy`, `HttpOnly`/`SameSite` cookies.
- English `README.md` with a French translation alongside it in `README.fr.md`, kept in step by three consistency tests (identical section structure, identical announced test counts, mutual links).

### Fixed

- Without JavaScript, two of the five pages did nothing and said nothing: the creation form's button had no effect, and the reading page announced "Loading…" for ever. Both now carry a `<noscript>` notice naming the reason — StashBin encrypts and decrypts in the browser — and "Loading…" is written by the script rather than by the HTML, so a page without one no longer promises something that will never arrive. Signing in, the inventory and its buttons work without a script, and the browser tests hold them to it.

- The interface was uncomfortable on a phone, without ever being broken. Fields inherited the 0.9rem of the label surrounding them and were rendered at 14.4px: below 16px, Safari iOS zooms the page in when a field takes focus and never zooms back out. They are now at 16px. Tap targets — buttons, the sign-out link, the "burn after reading" row — reach 44px on a touch pointer, the card no longer sits flush against the edges of a narrow screen, the text area is capped at half the viewport height so that a landscape phone still shows the submit button, and `:hover` is now behind `@media (hover: hover)`, since a tap used to leave the hovered shade stuck on the button. Five browser tests measure all this on a 360×640 screen, four of which fail against the previous stylesheet.

- The nginx configuration example for production did not set `client_max_body_size`: since nginx caps request bodies at 1 MiB by default, any secret between 1 and 2 MiB was rejected with a `413` before reaching PHP, even though `config.php` allows 2 MiB.
- The test bench's smoke journey (`containers/stashbin.sh test`) matched the API's error *messages*, which became translated: with English as the fallback, `grep 'introuvable'` no longer matched and two checks failed silently on every combination. It now matches the stable `code` field, exactly as the browser JavaScript does.

### Security

- A secret marked "destroy after first read" could be read by everyone who asked at the same moment. It was served first and destroyed after, leaving a window as wide as a whole PHP request: twenty simultaneous readers came away with seventeen copies of a secret promised to one. It is now claimed by a conditional write whose row count decides the single winner, and a test fires twenty readers at once and counts the bodies.
- Anyone holding a link could make the database grow without bound: every call wrote an access-log row carrying 200 characters of their choosing, on spent secrets as well, since a replayed link is worth recording. The log is now capped per secret (`access_log_max`), and the inventory renders no more than that many rows however many a database already holds.
- Nothing PHP serves may be cached any more (`Cache-Control: no-store`). The API's body is the ciphertext itself, which outlived a burnt secret in the reader's own disk cache, and the inventory carries the addresses of everyone who opened a link.
- Behind a TLS-terminating proxy — the deployment the README recommends — the session cookie was not marked `Secure`, because PHP sees plain HTTP and only the proxy knows better. `trust_proxy` lets an operator declare that proxy, which also makes the access log record the reader rather than the proxy. It stays off by default: those headers are written by whoever sends the request.
- An uncaught exception reached the visitor as a stack trace naming internal paths, under a `200` — a crash read as a success, which is how the race condition above stayed invisible. Exceptions now become a `500` and a stable `internal_error` code, with the detail in the server's log.
- The deletion link now requires an authenticated session in addition to the token: a link that leaks is unusable by a third party who is not signed in.
- A secret's owner may delete it from their inventory without holding the deletion token, and only their own: ownership and the token are two separate credentials, and neither grants the other. A signed-in stranger deletes nothing that is not theirs, and erases nothing from anybody else's history.
- The nginx example for production now places `try_files $uri =404;` before `fastcgi_pass`, so that a URL shaped like `/nonexistent/x.php` cannot cause another file to be executed.
